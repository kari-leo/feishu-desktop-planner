# 飞书桌面计划管理器｜开发需求

产品需求与技术规格 \| Windows 个人工具 \| v0.1 草案

目标：以已有飞书 Base 为任务主数据源，连接已有共享日历，在 Windows 桌面提供可交互的日历甘特图和当日待办挂件。自建应用负责授权与通信；同步服务及桌面程序为待开发的软件。

## 1 产品范围与关键决策

| **模块**       | **产品要求**                                                                               |
|----------------|--------------------------------------------------------------------------------------------|
| 飞书任务安排表 | 管理有排期或未排期任务；日历及甘特视图共用同一数据。                                       |
| 飞书每日待办表 | 独立管理每日待办；不自动生成共享日历日程。                                                 |
| 共享日历       | 只映射同时具有开始及截止日期的有效任务；允许修改已映射日程反向更新任务。                   |
| 桌面挂件       | 日历+甘特融合图、当日待办表；可编辑并写回飞书。                                            |
| 部署           | 首版纯本地、Windows 单用户；不需要云服务器或公网 Webhook。电脑关机时同步暂停，重启后补偿。 |

不做：多用户 SaaS、普通日历同步、聊天机器人、复杂项目依赖与资源调度。是否支持云端常驻服务作为后续决策。

## 2 总体架构

```text
Feishu Base (Schedule / Todo)  <-->  Sync Engine
Feishu Shared Calendar        <-->  Sync Engine
        REST API + WebSocket events / reconciliation
Sync Engine (Node.js, SDK, SQLite, TokenManager)
                  <--> local IPC <--> Desktop UI
Desktop UI: Calendar-Gantt Widget | Today Todo Widget
```

身份：Base 默认 tenant_access_token；共享日历使用 user_access_token；长连接使用 App ID + App Secret。同步引擎是唯一写入协调者；不并行开启原生工作流创建同一任务日程。

## 3 技术栈（建议，待技术验证）

| **层**      | **选型**                                                                                           |
|-------------|----------------------------------------------------------------------------------------------------|
| 桌面框架    | Tauri 2 + Rust + React/TypeScript；Node.js Sidecar 承载同步引擎。若打包复杂，Electron 为替代。     |
| UI / 状态   | FullCalendar（自定义跨日任务条）+ Frappe Gantt（可选时间线模式）；Zustand、dnd-kit、Tailwind CSS。 |
| 同步 / 存储 | @larksuiteoapi/node-sdk、SQLite、IPC；Win32/WorkerW 桌面集成，先验证无边框窗口。                   |
| 凭证        | Windows Credential Manager 或 DPAPI；前端不得接触 App Secret 或 Token。                            |

## 4 数据模型与同步规则

### 4.1 数据模型（字段映射需以实际 Base 为准）

| **实体**    | **必要字段 / 可选字段**                                                                                |
|-------------|--------------------------------------------------------------------------------------------------------|
| Schedule    | record_id、名称、开始日期、截止日期、状态；进度、优先级、分类、备注、全天标志可选。                    |
| Todo        | record_id、事项、计划日期、已完成；排序权重、优先级、备注、完成时间可选。                              |
| 映射与状态  | record_id + calendar_id + event_id；最后同步快照、同步状态、重试信息。日程 ID 建议回写 Base 隐藏字段。 |
| 本地 SQLite | schedule_cache、todo_cache、sync_mapping、sync_outbox；另存事件去重记录及 sync_token。                 |

### 4.2 多维表格、日历与桌面端行为

| **操作**                       | **系统行为**                                                              |
|--------------------------------|---------------------------------------------------------------------------|
| Schedule 新增 / 修改           | 两日期均有效且未取消：创建或更新映射日程。未排期任务只保留在 Base。       |
| Schedule 完成 / 取消 / 删除    | 完成保留历史日程；取消、清空任一日期或删除记录时，删除对应映射日程。      |
| Calendar 修改已映射日程        | 名称、起止日期、备注允许回写 Schedule；不覆盖进度、优先级等任务专属字段。 |
| Calendar 删除已映射日程        | 默认清空任务排期、保留记录；禁止直接删除任务。                            |
| Calendar 新增未映射日程        | 默认不创建 Base 任务、不接管无映射日程。                                  |
| Todo 新增 / 编辑 / 勾选 / 排序 | 仅同步 Todo 表；保留历史，不影响 Calendar。                               |
| 桌面交互                       | 先写 Base，成功后协调日历映射；显示真实同步状态。日历与甘特共用 Store。   |

说明：上表中取消、删除、反向同步字段等为基于前期讨论的建议规则，正式实现前可调整。

### 4.3 日期与事件映射

日期统一使用配置时区（建议 Asia/Shanghai，按用户实际环境调整）。Base 截止日按包含当天理解，内部转换为半开区间；全天事件结束边界以联调结果为准。禁止截止早于开始；日历任务默认空闲，不占用会议忙闲。

稳定映射、创建幂等键及本地快照避免重复日程；映射丢失时先核对远端，不能盲目重建。

## 5 飞书应用后台 / 同步引擎开发

### 5.1 功能模块

| **模块**            | **开发要求**                                                                                    |
|---------------------|-------------------------------------------------------------------------------------------------|
| Auth / TokenManager | 获取应用 Token；OAuth 首次授权、本地 HTTP 回调、state/PKCE 校验、自动刷新、凭证加密、重新授权。 |
| Bitable Client      | 获取表及字段，记录 CRUD、分页与筛选；以字段映射适配实际 Base。                                  |
| Calendar Client     | 查询共享日历、日程 CRUD；全量/增量同步，独立管理 sync_token。                                   |
| Event Receiver      | 建立 WebSocket、事件分发、资源订阅检查、重连、过滤目标资源，事件入队后快速返回。                |
| Sync Engine         | 执行字段映射、增量同步、删除处理、冲突合并、去重、重试及一致性检查。                            |
| Storage / IPC       | 缓存、持久化 outbox、映射、配置；向 UI 提供查询、编辑命令、状态和变更通知。                     |

### 5.2 OAuth 生命周期

保留 API 调试台重定向；正式程序通过系统浏览器使用本地回调（127.0.0.1:8765/oauth/callback，须实测）。OAuth scope 包含 calendar:calendar、offline_access，其他按接口需要开通。

首次授权保存 access_token、refresh_token、有效期、授权时间及 scope。Access Token 过期后可用有效 Refresh Token 刷新；不要求电脑持续开机。刷新互斥，成功后原子保存新凭证。Refresh Token 失效或授权满 365 天需重新授权。按照选定 OAuth 接口版本配套实现，禁止混用 v2/v3 请求格式。

### 5.3 事件与补偿同步

WebSocket 主通道；启动、休眠恢复、重连时补偿，建议每 5 分钟低频对账。日程变更通知仅作为拉取触发，使用 user_access_token 增量获取；sync_token 请求不同时传 start_time/end_time。若事件不支持长连接，使用该资源的轮询兜底。

事件 ID 去重、任务级串行队列、对比上次同步快照和字段级差异。不同字段自动合并，同字段冲突默认 Base 优先并记录。不能仅以最后修改时间推断更新来源。

离线操作先持久化 outbox；重试前判断是否已完成，失败使用退避。服务崩溃重启后恢复队列。删除需保留墓碑或映射，避免已删除记录被重建。

### 5.4 建议代码边界

```text
feishu/{auth,bitable,calendar,websocket,subscription}.ts
sync/{engine,mapper,conflict,reconcile,queue}.ts
storage/{database,repositories}.ts   ipc/{commands,events}.ts
```

## 6 Windows 桌面挂件开发

### 6.1 日历 + 甘特图融合挂件

默认月历：日期网格内呈现跨日任务条，展示名称、分类颜色、状态及进度；跨周任务分段呈现。支持月份切换、回到今天、溢出任务查看、任务详情。可选横向甘特时间线模式，支持日/周缩放，共享同一份 Schedule 数据。

| **交互**    | **需求及写回**                                                                          |
|-------------|-----------------------------------------------------------------------------------------|
| 新建任务    | 点击日期/拖选日期区间，弹出任务编辑；保存后新增 Base 记录并创建对应日程（满足条件时）。 |
| 调整任务    | 拖动任务条修改排期，拖拽边缘改变起止日期；校验日期有效性，失败时提示及恢复/待重试。     |
| 编辑任务    | 点击任务打开浮窗，修改名称、日期、状态、进度、优先级及备注。                            |
| 删除 / 取消 | 明确确认删除；按同步规则处理日历映射。                                                  |
| 状态呈现    | 显示同步中、已同步、离线待同步及失败；可手动刷新。                                      |

### 6.2 今日待办挂件

今日待办列表展示所有未完成事项，包括已逾期、计划在未来和未设日期的事项。待办按用户设置的前后顺序排列，优先级通过行缩进体现。缩进默认开启，可在挂件外观设置中关闭。挂件勾选或飞书表格同步使事项完成时，该事项淡出列表；在飞书表格取消完成后，事项重新出现在挂件。挂件支持快速新增、设置优先级、勾选完成、编辑、删除和拖拽排序，保留历史记录。挂件操作只写回 Todo 表。

### 6.3 桌面系统集成

两个独立挂件分别保存布局，支持透明度、配色、托盘、自启动和手动刷新。浏览模式隐藏窗口栏和窗口控制按钮，允许用鼠标与键盘增删改日程及待办，设置入口放在挂件内容区。布局编辑模式提供移动和调整大小的操作。应用窗口可覆盖挂件，不强制置顶。

先开发无边框交互窗口，再验证 WorkerW 桌面嵌入。需要测试 Win+D、Explorer 重启、DPI、多屏、休眠恢复和鼠标键盘交互；若不稳定则退回普通浮动窗口。

### 6.4 本地设置与错误反馈

配置页：飞书连接状态、Base/两表 ID、目标 Calendar ID、字段映射、时区、刷新间隔、重新授权、挂件外观及布局。凭证仅通过安全存储模块访问。

不显示敏感 Token，不在日志输出完整凭证或任务内容。授权失效时提示重新登录；网络错误与权限错误分别反馈；局部失败不应阻止读取缓存。

## 7 开发里程碑与验收

| **阶段**          | **交付与验收标准**                                                                                     |
|-------------------|--------------------------------------------------------------------------------------------------------|
| M0 通信验证       | 按独立配置手册验证两张表、共享日历 CRUD 与事件接收；记录权限、事件结构、日期语义。                     |
| M1 同步引擎       | 完成 OAuth、Token 持久化、映射与同步：Base 新增/改期/删除反映到日历；日历改期反映回 Base；无重复日程。 |
| M2 桌面 MVP       | 无边框月历甘特图 + 今日待办；任务新增/编辑/拖拽及待办勾选/排序均写回；同步状态可见。                   |
| M3 可靠性与桌面化 | 断线补偿、离线队列、冲突合并、桌面嵌入、托盘、自启动、布局保存及安装包。                               |

### 7.1 关键验收用例

| **场景**                | **预期**                                                    |
|-------------------------|-------------------------------------------------------------|
| 任务有起止日期 / 缺日期 | 前者生成唯一日程；后者不生成；清空日期删除已映射日程。      |
| 三端修改                | 桌面拖拽、Base 修改、日历改期均按规则收敛；不出现循环写入。 |
| 独立待办                | 桌面勾选后 Base 更新；飞书编辑后桌面更新；无日历日程。      |
| 离线 / 重启 / 重复事件  | 缓存可读；队列恢复、重试幂等；重启后补偿，不丢操作。        |
| Token 过期 / 授权撤销   | 可刷新则无感恢复；不可刷新则提示授权；不泄露凭证。          |
| 日期边界 / 系统窗口     | 跨月、跨年、全天、时区正确；窗口在目标 Windows 环境可交互。 |

### 7.2 风险与未决事项

实际字段 schema 和 ID 未提供，需配置映射；共享日历事件能否通过长连接接收、应用对 Base 订阅权限、OAuth loopback URL 需实测。WorkerW 依赖 Explorer 实现，不保证所有 Windows 版本。未进行性能测试，不设未经验证的延迟承诺。

已选 WebSocket + 低频补偿、混合身份、本地部署。日历删除语义、全天规则、冲突优先级、UI 栈属于建议默认值；桌面开发前确认。
